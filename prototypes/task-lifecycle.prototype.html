How do task, run and attention-request lifecycles fit together?

Press buttons and watch a task, its runs and its attention requests move. This explores handoff (HITL → AFK), how a run's ending drives the task, how an attention request pauses a run, how child tasks roll up through a task tree, and whether a group has any state of its own. Every rule here is a proposal. The interesting moments are the ones that make you say "that shouldn't happen".

Proposed rules

  1. A task is in one of: Draft, Queued (AFK) / Ready for you (HITL), Running / In conversation, Needs you, Waiting on children, In review, Done, Cancelled. There is no "failed" task state: a failed run raises an attention request, and the operator retries or cancels.
  2. A run has one mode and is Active, Suspended, or Ended with an outcome. A task's history is its list of runs; consecutive runs resume the same Claude session.
  3. Handoff ends the HITL run and queues the task as AFK at a chosen autonomy level. Take over is the reverse: it ends (or supersedes) the AFK run and opens a HITL conversation on the same session.
  4. An attention request suspends its run: the session stays open, using no tokens and no parallel slot. Answering resumes the same run. If it waits too long (or the factory restarts), the run is parked (ended); answering then queues a new run that resumes the session.
  5. HITL runs never raise attention requests: the agent asks in the conversation. A HITL task between runs shows up as "Ready for you".
  6. The scheduler starts queued AFK tasks while active AFK runs < the cap and the usage window is open. HITL runs start only when the operator opens them. When the window runs out, active runs stop and their tasks return to the queue.
  7. An agent in an active run can spawn child tasks (AFK, autonomy ≤ parent, same groups, depth ≤ 2), awaited or fire-and-forget. Waiting on children ends the parent's run; when every awaited child is Done or Cancelled, the parent is queued to resume with their results.
  8. A child task finishes as Done and reports to its parent. Only a root task goes to In review (draft PR at L2, local branch at L1). Only the operator moves it to Done (merge) or back to the queue (request changes).
  9. Cancelling a task cancels its whole subtree. A child's attention request bubbles up to its root's summary line.
  10. A group is only a label set. Its "state" is a count derived from its tasks. Children inherit their parent's groups.
  11. In a workflow preset, finishing a stage queues the next one. A HITL → AFK stage boundary is a handoff the preset makes. The operator can also hand off early, which skips the remaining HITL stages and goes to the next AFK stage.

Settled with the operator

  • An attention request suspends the run, and a parked run resumes in a new run.
  • No Failed task state: failure lives on runs.
  • Children report to their parent; only the root is reviewed.
  • Autonomy covers AFK only (L1, L2). L0 is dropped.
  • Answering a suspended run resumes it at once, even over the cap.
  • A preset task can be handed off early.
  • A root can be reviewed and merged while fire-and-forget children run on.
  • A group is only labels.
